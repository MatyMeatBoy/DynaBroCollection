- `games/checkpoint_launcher.c`'s child-exit handling now checks `GetExitCodeProcess` and closes the launcher entirely (same as a direct `--game` CLI launch) when the exit code is 42, instead of unconditionally reappearing.
- 54/54 native contracts (new `manual_data_contract` included) and 111/111 Python tests still pass after rebuilding both games.
**Not verified with a human/real input**: per item 14 above, this runtime UI reads real OS keyboard/controller events directly and is invisible to `native_probe --input-script`, so there is no scripted way to confirm the three menu items actually appear, navigate correctly, and produce the right exit code/relaunch behavior.
