# Dyna Brothers v0.2.0 — Windows x64 checkpoint

Run DynaBrothersLauncher.exe with the extracted files together. Public packages require supported original dumps in roms/ or the executable folder. The private personal package includes the owner's original dumps. English defaults on.

This checkpoint preserves v0.1.9's DB1/DB2 features and grows the DB2 Special translation catalog from 454 to 582 entries: the title OPTIONS menu and sound-test names, the Custom Versus settings screen and COM difficulty names, Practice briefings 2-6, and stage-2 RAM cutscene dialogue are now translated and verified on screen, and the 3-line gameplay prompt boxes are centered correctly.

DB1 native rendering fix: a single actor whose RAM record is transiently unreadable (for example the frame it dies on) no longer drops the entire frame back to centered-native/4:3 presentation — only that one actor's own sprite is skipped for the bad frame, while terrain, HUD and every other actor keep rendering in the configured widescreen/Enhanced presentation. This has a dedicated native regression test and likely explains two owner reports: a brief 4:3 flash when a player unit dies, and a visual glitch right after issuing an order to a unit. Also fixed: lightning/tsunami hazard weather clouds now fill the full widened canvas instead of stopping at the native 320px edge.

Launcher: each game card now shows an isometric box-art cover built from real Sega Retro box scans, with a hover/focus-triggered cartridge-reveal animation. The mouse cursor auto-hides after 1 second idle in fullscreen or borderless mode, since both games are controller/keyboard-only. The in-game host menu gained three new actions: Restart Level, Return to Title Screen, and Quit to Desktop. `recomp-launcher.json` declares `DynaBrothersLauncher.exe` as the single supported entry point for third-party recomp-launcher frontends, with both games' standalone executables marked as internal child processes a frontend shouldn't list separately.

Known remaining DB2 gaps: the in-game Options menu's text and Original mode's kanji stage names are suspected baked tile graphics, not ROM text (same class of problem as before). Newly tracked: a subtle, low-severity graphical glitch on fast-moving DB1 actors near the HUD/world-viewport seam, and a DB1 title-menu highlight-timing question around the Extras row wraparound. See [STATUS.md](../../STATUS.md) and `docs/handoff/PENDING.md` for the full list and the evidence behind each item.

The green launcher contains settings for either game. Start+Mode/Select opens the in-game host menu. Known M30 identities select the Genesis six-button layout; physical firmware variants still require hardware testing. Original preserves 4:3. Enhanced targets 16:9.

Verification includes the full native contract suite and Python test suite, both green on this checkpoint. Packaged checks additionally exercise an actual typed Normal2 password and B+direction camera route in six-button mode, comparing Original/Enhanced canonical guest and audio state. Exact packaged results are recorded in PACKAGE.json after qualification.

Known limit: DB2 can temporarily fall back to the native image during held camera movement and initial frames. Released camera captures preserve exact world and HUD pixels at their projected offsets. Continuous widened scrolling, whole campaigns, all hazards and physical audio/controller output are not claimed complete. DB2 English remains partial. This is a checkpoint, not a finished recompilation.

A separate private development toolkit restores sources, pinned dependencies, portable tools, private inputs and generated code on another Windows x64 PC. Read docs/handoff/CONTINUE-ON-ANOTHER-PC.md. Keep private packages and toolkits private.
