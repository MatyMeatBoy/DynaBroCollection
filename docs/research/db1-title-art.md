# DB1 presentation title art

## Current revision: native backing anchored at canvas bottom

The v0.1.5 field report rejected the artificial bottom band and exposed green English-logo outlines. The implementation now samples **no bottom generated pixels**. `db1_title_art_geometry(height, native_top, 224)` sets the presentation backing shift to `height-native_top-224`. Native plane B samples use `line-shift`, so its original authored row223 reaches the canvas bottom. Only sky above original row0 is synthesized from the optional generated top32 rows; further sky uses the top sky raster. Horizontal/raster/column scroll comes from the same native plane-B coordinate helper at the shifted source row. Native simulation, plane A and sprite screen positions do not move.

The row compositor reconstructs this shifted backing only where native plane A and SAT are transparent. It tests actual pattern opacity, never RGB equality, preserving the Japanese logo, PRESS START, native menu and sprite copyright even when their colors equal the background. English replacement still removes only the identified Japanese logo patterns and alpha-composites the approved PNG at its native plane-A coordinates. Integration must call the geometry helper after setting canvas geometry.

The outline defect came from a reference dump taken partway through the white fade. Several actual black/gray channels were floored to `0x444`, so distance quantization confused black with another palette owner. Correlating the original native Japanese capture at frame2901 against each logo-pattern nibble proves nibble15/CRAM31 owns6193 black outline pixels; nibble9 has34 other black pixels. Nibble14 is RGB49 gray, nibble13 RGB87 gray, nibble2 RGB174 gray. The corrected canonical logo palette uses those stable original colors, excludes transparent slot16 and pins quantized opaque black to semantic CRAM31. It continues resolving **live normal-level CRAM31**, becoming black during black fade and white during white flash; it does not paint static black that would survive the flash. No `1+2` graphic is introduced in the game.

Pure tests now cover bottom-band refusal, bottom-anchor geometry, exact/near-black semantic palette ownership even when unused slot16 is green, white/black endpoints, native opaque plane-A preservation and alpha. Native before/after verification for this revision passed after the root-owned relink; see the current qualification below. The notes below describe earlier validation and are historical where they mention bottom bands or the faded reference palette for the logo.

## Earlier evidence

The title VDP snapshot in `local/evidence/db1-intro-agent/title-vdp.bin` identifies the Japanese logo as **plane A**, not sprites. Plane A starts at VRAM `0xc000`, has 64 columns and uses palette line 1 with tiles `0x102..0x262`. Its tile envelope is native x=48..271, y=24..143. The two guard attributes are `0x2102` at column13,row3 and `0x2262` at column31,row17. PRESS START uses row20 and tile IDs around `0x300`; copyright is in SAT. Neither belongs to the replacement mask.

`db1_title_art_row` is a read-only presentation compositor. It requires TITLE scene classification, display enable, normal noninterlaced 512x256 plane geometry and both logo attributes before doing any work. It removes only nontransparent pixels from the identified original logo tile range, reconstructing the live plane B behind them. The exact approved `assets/img/dyna-logo-v1.png` is nearest sampled with its alpha into that same 224x120 tile envelope. Plane A H/V scroll controls its position. Translation off skips logo replacement. A missing logo leaves the original intact.

The optional `assets/img/db1-title-background-512x288.png` is normalized to logical 512x288 (the delivered generation is 1672x941), with the original 224 rows at logical y32..255. Dimensions must be 512..4096 wide, 288..4096 high and within about 1% of 16:9. Only authored source rows -32..-1 and224..255 can be sampled. X wraps512. The compositor obtains signed source coordinates from `db1_scenes_plane_b_coordinates`, including native column/raster scroll and clamped edge columns. Added bands are applied only outside the original native picture; the native foreground remains authoritative. Missing or invalid assets cause no replacement.

The 64 reference CRAM words are extracted from the title snapshot at byte65536, little endian. Band colors quantize to background palette line3; logo colors quantize to logo palette line1. Each nearest match stores a CRAM index and normal DAC level. Every presented pixel resolves that token against **live CRAM**, so black fades remain black and palette changes remain active. Synthetic shadow/highlight matches are excluded: the native title has shadow/highlight disabled (reg12=0x81). Shadow tokens produced gray logo ghosts during the actual all-white entry fade; highlight black would glow during a black fade. RGB distance uses the authentic nonlinear Genesis DAC. Equal colors resolve deterministically to the first normal match. A generated RGB image cannot encode which of several identical palette entries was intended; duplicate entries and differing future palette cycles remain ambiguous. The approved logo's shape and alpha are preserved, while its colors are constrained by the native title palette.

Pure tests cover bounded band coordinates, X wrapping, integer and normalized scale, alpha endpoints, live palette black, scene/display/interlace guards and unchanged nonlogo rows/VDP memory. They do not prove native motion or fade cadence. That requires captures of the actual ROM title animation and transitions. This module does not write ROM/RAM/VDP state, jump the PC or change native timing.

Asset initialization decodes the original PNGs, then retains only nearest samples at the displayed logical resolution. It quantizes at most 512x64 band pixels and224x120 logo pixels; the unused background middle is never quantized. A standalone unoptimized test process with the delivered assets measured1103ms before this reduction and291ms after (including process/PNG decode overhead), rather than a native frame timing claim.

The current build preloads the artwork before starting the frame loop. The packaged `db1-title-background-native.png` and `db1-title-logo-native.png` use the same integer sample coordinates as the original loader. Regenerate them with `python tools/prepare_db1_title_art.py` after changing the source art. The original PNGs remain a fallback when the smaller assets are missing or fail to load. DB1's original display composes only the 224-pixel-wide logo region, with the same native coordinates and live palette.
