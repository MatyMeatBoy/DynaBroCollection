# v0.1.3 DB1 widescreen and achievements plan

**Goal:** Deliver a verified DB1 expanded-world 16:9 test, achievements popup/list support and an immutable portable Windows ZIP/public test release. DB2 keeps its original presentation and gains a code-backed local achievement set based on confirmed modes/progression.

**Design:** DB1 receives a game-owned, read-only scanline compositor. Preserve the original world pixels, extend actual terrain/actors into the additional region and anchor the HUD at the new right edge. Decode authoritative 40-stride world data and original actor animation/pattern streams; never expand the guest's fixed 36-actor buffers. Unsupported scenes use a complete centered native image. Original mode must retain original rendering and input behavior. A fixed 16:9 canvas uses the closest whole-pixel width to height*16/9, with optional maximum integer presentation; adaptive window ratios remain bounded. Explicit world-cursor changes must be gated to the enhanced mode and qualified separately from menu cursor paths.

**Achievements:** Follow ReKHCom's embedded catalog/local timestamps/badge popup/list model. All 76 DB1 public entries and both badge variants were recovered; authenticated evaluator definitions were not publicly available. The implementation therefore uses independently verified native event contracts and public author hints, documented in `docs/db1-achievement-contracts.md`, without claiming exact RA evaluator equivalence or account synchronization. DB2 Special's set is local, with verified campaigns and its own IDs/character badges; no hard campaign is invented.

**Protected artifacts:** All existing archives and user dumps remain unchanged. Test profiles are isolated. ZIP includes runtime dependencies, permitted assets, diagnostics and instructions; the player selects their own cartridge dump. Public release is authorized by the user and will be marked a test/prerelease if remaining experimental scope requires it.
